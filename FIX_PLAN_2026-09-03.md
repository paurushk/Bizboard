## 1. How to use this document

- **Section 6 (Master tracker)** is the source of truth. One row per finding: `ID · Severity · Cluster ·
  Workstream · Phase · Effort · Status · Fix summary`. Flip `☐ → ☑` (or `▶` in-progress, `⤬` won't-fix with a
  reason) as work lands. Add `PR#` / `Owner` columns in your fork if you want.
- **Section 5 (Workstream catalogue)** groups the 473 findings into **28 thematic workstreams** (shared root
  cause → one design, many findings closed) plus **11 module "owner buckets"** (`WS-B1 … WS-F3`) for findings
  that don't consolidate and are best handled by that module's owner.
- **Section 4 (Phases)** is the delivery order: **P0** (3 Critical hotfixes) → **P1** (44 High + the systemic
  workstreams) → **P2** (Medium) → **P3** (Low) → **P4** (Info / backlog).
- Workstream tags are an **initial triage grouping**, assigned semi-automatically from each finding's fix
  text. Task 0 of the plan is a 1-day grooming pass to confirm them. The finding IDs and severities are
  authoritative; the WS/Phase/Effort columns are planning aids.
