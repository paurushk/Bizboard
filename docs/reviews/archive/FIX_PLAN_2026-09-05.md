## 8. Phase 0 — Hotfix (PR 1, PR 2)

### PR 1 — Refunds + RLS (R-002, R-003, R-005, R-031, R-053) · hints R-090, R-091

#### R-002 / R-003 — event map + one logical refund

When `PAYMENTS_REFUND_EVENT_MAP_V2` is true:

- `refund.processed` → unwind (`REFUNDED`)
- `refund.created` → **ignore** (no money path)
- `refund.failed` → `FAILED` (webhook already ignores non-CAPTURED / non-REFUNDED)
- Remove `event.startswith("refund.") → REFUNDED`

**Provider refund id:** key `applied_refund_keys` / skip_gateway on the Razorpay refund entity id (`rfnd_*`).

**Fallback when the provider omits the refund id** (older payloads):

1. `"{provider_payment_id}:amt:{quantized_amount}:processed"` for `refund.processed` (created is ignored, so created+processed still once).
2. If amount is also missing: `"{provider_payment_id}:evt:{razorpay_event_id_or_body_sha256}"` and **log `refund_id_missing`** at error. Do not invent a new `refund_seq` per webhook event.

**DoD:** failed refund leaves CAPTURED + allocations; two signed events for the same `rfnd_*` reverse once; missing-id processed still reverse once.

#### R-005 / R-031 — webhook RLS

**Signature vs lookup (constraint):** payment webhooks are **per-company secrets**. HMAC cannot run before a DB lookup that yields the company. Billing SaaS webhook **can** verify first (`RAZORPAY_WEBHOOK_SECRET` is instance-level) — keep that order.

Payment webhook order:

1. Unsigned **probe parse** for `payment_link_id` only (no money mutation).
2. `with rls_bypass():` load `PaymentLink` by `provider_link_id` + provider. Ambiguous → 409. Missing → 400 (same as today).
3. If the company row is missing (wipe) → **410**, do not settle. Subscription lapsed does **not** block customer payment settlement.
4. **Then** `adapter.verify_webhook` with that company’s credentials. Fail → 401. **No** `ProcessedWebhookEvent` yet.
5. `set_rls_company(company.id)`.
6. Insert `ProcessedWebhookEvent` **under the tenant GUC** (dedupe is per-company, after signature). A spoofed `payment_link_id` still fails step 4.
7. Money path (`finalize` / `refund_gateway_payment`).

Billing: verify HMAC (already first) → probe subscription id → `rls_bypass` load Subscription → missing/wiped company → 410 ignore → `set_rls_company` → `ProcessedWebhookEvent` under GUC → apply status.

**DoD:** `@pytest.mark.postgres` + `POSTGRES_RLS_ENABLED=1`: capture settles; billing updates subscription; unsigned probe cannot insert dedupe.

Settings default `"0"`; compose already `:-0`; README + `.env.example` match. Comment: CI `postgres-rls` sets `1`.
