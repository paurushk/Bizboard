# Architecture

Consolidated reference for how Bizboard is built. Source of truth is the code;
this document is kept short so it stays accurate. For the reasoning behind
individual choices see [`reviews/ARCHITECTURAL_DECISIONS.md`](reviews/ARCHITECTURAL_DECISIONS.md)
(ADR-A01…A10).

## Shape

Monorepo, three deployables plus docs:

| Path | What | Stack |
|---|---|---|
| `backend/` | REST API, business logic, async jobs | Python 3.12, Django 5, DRF, SimpleJWT, Celery, drf-spectacular |
| `web/` | SPA | React 18, MUI 6, Vite 6, TanStack Query, react-hook-form + zod |
| `mobile/` | Android WebView shell over the `web/` build | Capacitor 6 |
| `docs/` | This tree | Markdown |

Data stores: PostgreSQL in production (`DATABASE_URL`), SQLite fallback for
local/test; Redis as the Celery broker (eager in-process mode by default for
local/dev).

## Backend layout

`backend/` is ~19 Django apps under a service-layer pattern:

- **Domain apps** — `sales`, `purchases`, `inventory`, `payments`, `masters`,
  `ledgers`, `reporting`, `accounting`, `banking`, `billing` (SaaS entitlements),
  `crm`, `manufacturing`, `payroll`, `insights`, `imports`, `integrations`,
  `search`, `accounts` (tenant/company/user).
- **`core`** — cross-cutting: auth, permissions, RLS, idempotency, feature
  flags, notifications, LLM, PDF/file assets, help system, domain-event bus,
  middleware, pagination, renderers.
- **`config`** — `settings.py` / `settings_test.py`, `urls.py`, `celery.py`,
  `wsgi.py` / `asgi.py`.

Request flow: **thin viewset → service module → models**. Views do
serialization and permission checks only; all business rules live in
`<app>/services.py`. Cross-app side effects go through the in-process event bus
(`core.events`) — there is no message broker in the MVP path.

## Invariants (do not break during refactors)

1. **Completed business documents are the source of truth.** Invoices, bills,
   returns, and payment allocations are the ledger.
2. **No customer/supplier ledger tables.** Party balances are *derived* by
   `ledgers/services.py` (`LedgerService.bulk_*_outstanding`) from documents +
   allocations. (ADR-A01)
3. **GL is a projection, never a second editable money truth.** The optional
   `accounting` books re-derive from documents (+ sparse manual journals). (ADR-A02)
4. **Stock movements are typed and append-only** (`inventory` `stock_movements`,
   typed `movement_type`); `stock_balances` is a rebuildable cache.
5. **Document completion and inventory effects are atomic.**
6. **Document numbers** are assigned on Complete via `DocumentNumberService`
   using row-locked sequences (`select_for_update`; the `postgres` pytest marker
   covers this).
7. **Every business query is scoped to `company_id`;** child rows carry their own
   `company_id`. (ADR-A08)
8. **Public API is versioned under `/api/v1/`.** OpenAPI is generated by
   drf-spectacular; `docs/openapi-snapshot.json` is the committed snapshot that
   drives `web/src/api/openapi-types.ts` (a CI check enforces it exists).
9. **Filed statutory periods are immutable.** (ADR-A06)
10. **Sandbox statutory surfaces never render as live GSTN filing.** (ADR-A04)

## Multi-tenancy

Shared-database, shared-schema. Isolation is enforced in application code via
`company_id` scoping on every queryset. Postgres row-level security exists
(`core/rls.py` + RLS migrations + Celery GUC propagation in `config/celery.py`)
but ships **disabled** (`POSTGRES_RLS_ENABLED=0`) until proven. (ADR-A03 is
Postgres-only production.)

## Feature flags

Advanced surfaces are gated and **dark in production pilots** unless explicitly
enabled: GSTR report screens, e-invoice / e-way submit, `accounting` books, AI
insights, Tally sync, POS, `manufacturing`, `payroll`, `crm`, WhatsApp Cloud,
AA banking. Backend gate: `ENABLE_*` env + per-company `feature_flags`
(`core/services/feature_flags.py`). Frontend gate: `VITE_ENABLE_*` /
`VITE_PILOT_ADVANCED`. The code for these modules is real and tested — it is not
dead code. (ADR-A07, ADR-A10)

## Frontend

`web/src/` — `pages/` (~170 route components), `components/`, `hooks/`, `api/`
(axios client + per-domain modules; `api/legacy/*` is the older barrel still
re-exported via `api/resources.ts`, `api/typedClient.ts` + `openapi-types.ts` is
the typed successor), `offline/` (IndexedDB draft outbox with localStorage
fallback, shared by the invoice editor and POS), `i18n/` (English + Hindi).
PWA via `vite-plugin-pwa`: app-shell precache + `offline.html`; authenticated
`/api` responses are **not** Workbox-cached; sign-out purges the caches.

## Async work

Celery app is `config.celery`. Local/dev runs eager (`CELERY_TASK_ALWAYS_EAGER=1`).
Non-eager needs `REDIS_URL` and a worker (`celery -A config worker`). Main async
job is A4 PDF rendering — document Complete returns immediately and the PDF is
rendered in the background. `beat` schedules periodic jobs (help-event pruning,
etc.).

## Deployment

`docker-compose.yml` (local full stack: `db`, `redis`, `migrate`, `api`,
`worker`, `beat`, `web`, `nginx`, optional `clamav`, plus `backup` / `restore` /
`test` helpers). `docker-compose.prod.yml` layers the production `api` / `worker`
/ `beat` / `migrate` / `clamav`. `nginx/` terminates and serves the built SPA.
`scripts/` holds `backup.sh`, `restore.sh`, `pin_image_digests.sh`. See
[`reviews/12_DEVOPS_REVIEW.md`](reviews/12_DEVOPS_REVIEW.md) and
[`pilot/RUNBOOKS.md`](pilot/RUNBOOKS.md).
